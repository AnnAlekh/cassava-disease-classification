# 🗺️ Roadmap проекта Cassava Disease Classification

Этот документ описывает план развития проекта в ближайшие месяцы.

## 📅 Краткосрочные цели (Q1 2024)

### ✅ Текущая версия (v1.0.0)
- [x] Базовая модель классификации (EfficientNet-B0)
- [x] FastAPI backend с REST API
- [x] Flutter мобильное приложение
- [x] Docker контейнеризация
- [x] Базовая документация

### 🎯 Ближайшие задачи (v1.1.0)

#### Улучшение модели машинного обучения
- [ ] **Внедрение Focal Loss** для работы с дисбалансом классов
  - Цель: Улучшение macro F1-score с 69.25% до 72-75%
  - Оценка: 2-3 дня работы
  
- [ ] **SMOTE oversampling** для minority классов (CBB, CBSD)
  - Цель: Улучшение precision для редких классов
  - Оценка: 1-2 дня работы

- [ ] **MixUp/CutMix аугментации** во время обучения
  - Цель: Повышение обобщающей способности модели
  - Оценка: 1 день работы

- [ ] **Test-Time Augmentation (TTA)** для инференса
  - Цель: Улучшение точности предсказаний
  - Оценка: 1 день работы

#### Улучшение API
- [ ] **Аутентификация и авторизация**
  - JWT токены для безопасного доступа
  - Rate limiting для защиты от злоупотреблений
  - Оценка: 2-3 дня

- [ ] **Кэширование предсказаний**
  - Redis для кэширования результатов
  - Оптимизация повторных запросов
  - Оценка: 1-2 дня

- [ ] **Мониторинг и логирование**
  - Интеграция с Prometheus для метрик
  - Структурированные логи (JSON)
  - Health checks с детальной диагностикой
  - Оценка: 2 дня

- [ ] **WebSocket поддержка** для стриминга результатов
  - Реал-тайм предсказания
  - Уведомления о статусе обработки
  - Оценка: 2-3 дня

#### Улучшение мобильного приложения
- [ ] **Офлайн режим**
  - Кэширование последних предсказаний
  - Сохранение истории сканирований
  - Синхронизация при появлении сети
  - Оценка: 3-4 дня

- [ ] **Улучшение UX**
  - Анимации и переходы
  - Индикаторы загрузки
  - Обработка ошибок с понятными сообщениями
  - Оценка: 2-3 дня

- [ ] **Расширенная статистика**
  - Графики истории сканирований

  - Экспорт отчетов
  - Оценка: 3-4 дня

## 🔄 Процесс разработки

### Git Workflow
- **main** - Стабильная версия для продакшена
- **develop** - Основная ветка разработки
- **feature/** - Новая функциональность
- **bugfix/** - Исправления багов
- **release/** - Подготовка релиза
- **hotfix/** - Критические исправления

### Code Review
- Все изменения проходят код-ревью перед мерджем
- Минимум 1 одобрение для feature веток
- Минимум 2 одобрения для изменений в main

### Тестирование
- Unit тесты для критических компонентов
- Integration тесты для API
- E2E тесты для мобильного приложения
- Целевой coverage: 80%+
